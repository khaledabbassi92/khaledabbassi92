# `01 // WHO I AM`

I am a computer science engineer interested in **how software actually becomes a system**.

I don't want my work to stop at:

> *"It works."*

I want to know:

> **Why does it work?**

Then:

> **What happens when it gets bigger?**

Then:

> **What happens when it fails?**

And eventually:

> **Where is the limit?**

That mindset naturally pulls me toward **systems programming, software architecture, networking, distributed systems, compilers, servers and real-time applications**.

I enjoy the point where software stops being a collection of functions and starts becoming an ecosystem of interacting components.

That's where architecture matters.

That's where trade-offs matter.

That's where failure becomes interesting.

I don't see failure as the opposite of engineering.

**Failure is information.**

A broken system exposes assumptions.

A bottleneck exposes architecture.

A crash exposes a boundary.

A scaling problem exposes a design decision.

A difficult bug exposes something I didn't understand deeply enough.

That is the part of development I find valuable.
